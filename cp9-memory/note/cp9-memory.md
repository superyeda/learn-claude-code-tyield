# Memory

## 流程
加载-提取-整理-存储
1. 索引注入：对话开始前，将记忆索引注入到system prompt中
2. 按需加载：通过用户最近的消息，通过LLM从记忆索引中选出相关的记忆内容，注入到用户消息之前
3. 自动提取：每轮对话结束后，获取最近10轮的对话结果，发个LLM，提取其中的用户偏好、约束、项目信息等，返回数组，写入.memory/*.md中，更新索引
4. 记忆整合：当记忆文件数量超过阈值时，所有记忆文件发给LLM，让LLM合并重复、删除过时、保留重要的，删除旧文件，写入整合后的新文件。
5. 压缩前快照：压缩过程会丢失细节。提取记忆采用压缩前的完整对话内容，确保信息完整。

## 记忆类型
- user: 你是谁
- feedback：这么做事
- project：正在发生什么
- reference：东西在哪找

两类记忆
- 索引常驻SYSTEM
- 相关记忆按需引入

## CC源码
- Feature flags：记忆相关的功能有多层feature gate控制
- Team memory：团队共享记忆有专门路径
- KAIROS：时机感知记忆提取策略
- Prompt cache：记忆注入需要考虑prompt cache的TTL，避免每次都重写system prompt的大段内容
- 文件锁：多进程并发时的锁机制
- Memory prefetch：异步预取，不阻塞主流程
